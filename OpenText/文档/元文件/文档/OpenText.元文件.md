##### [[OpenText.索引.元文件|OpenText 元文件]]
- OpenText 元文件
	- **OpenText 元文件**是对 [[OpenText]] 文档的内容, 结构及其整体规划进行解释与说明的文件. OpenText 文档分为元层和内容层. 元层并不直接承载具体的知识, 而是为所有页面提供组织原则, 结构约束与演化方向, 从而保证整个文档体系在长期扩展过程中保持一致性, 连续性与可维护性. `OpenText` 是元层文件的命名空间, 两个子空间是 `OpenText.元文件` 和 `OpenText.索引`. 其中, 索引是导航结构, 只简单链接模块内的核心内容, 确保文件夹内任意文件都可以被反向链接到某个索引. 内容层是文档主体, 自由命名, 部分容易歧义的内容也划定了命名空间. OpenText 文档按模块递归定义, 包含索引文件, 元文件, 内容文件的就是一个模块, 模块本身也是一个内容节点. `OpenText` 是顶级模块, `元文件`, `人文社科`, `自然科学`, `形式科学` 是四个次级的模块, 接着在这些模块中定义了更多子模块, 但是遵循少层级, 宽扁平的原则, 没有嵌套过深. 这种结构的主要缺陷在于唯一物理位置和多重语义归属的冲突, 本质上也是用文件树结构承载知识图结构产生的冲突, 难以避免. 只能说为概念词条选择一个主锚点领域, 将其存储于最早系统化定义或最主要形式化表达的学科

```
Module ::= {
  Meta      : File | Folder,
  Index     : File | Folder,
  Contents  : Set<ContentNode>
}

ContentNode ::= File | Folder(Module)
```


> [!summary]- 英语
> - [[OpenText.索引.英语|英语文档]]试图提供一个融洽的语法框架, 表述难免存在矛盾冲突, 也会忽视细枝末节的语法比如单个词的应用. 在自然语言语法理论中, 功能语法强调句子的语法功能, 如主语表示主题, 宾语表示受事, 适合快速理解句子核心意义, 而成分语法将句子分析为若干层次的短语成分, 强调句法结构的分层性和形式化, 如主语通常对应名词短语, 谓语对应动词短语. 递归性是短语结构的核心原则, 句子是由短语逐层嵌套构成的. 下图是自然语言的语法树类似于编程语言的抽象语法树, 用于生成语法理论和自然语言处理等. 但是不管什么语法, 有限的规则难以完全表示自然语言, 总有例外难以自洽. 英语单词库设计标签与记忆属性, 具体参考 [OpenWords](https://github.com/insile/OpenWords) 插件. 每个单词统一小写, 自行辨认需要大写的单词, 存在意义不明和使用频率很低的词汇或词性. 同一词根借助前缀或后缀存在很多派生词. 专有名词不全例如国家, 城市等. 由于文件名不能为 `con` 该单词换为 `con'`. 英语短语按作用词性由作者人工分类, 可能有误. 英语词法页面只索引一些比较重要的单词, 英语单词页面会索引全部. 必修包括小学, 中考, 高考四级三种标签, 其中中考去除小学词汇, 而高考四级去除小学, 中考词汇. 选修包括考研, 六级, 雅思, 托福, GRE 五种标签, 并且全部去除必修词汇. 必修单词为单标签, 意思是每个单词只有一个类别标签, 选修单词为复合标签, 意思是每个单词有多个类别标签

> [!summary]- 数学
> - [[OpenText.索引.数学|数学文档]]在内容层面之前, 首先引入了一组元数据用于文件管理, 可通过数学视图进行集中审查与浏览. 目前已定义的字段包括`创建时间`, `更新时间`, `页面类型`, `更新次数`, `准确率`, `完整度`, `阅读状态`. 其中, `页面类型`用于区分文件角色, `0`表示索引文件或元文件, `1`表示词条文件. `准确率`与`完整度`是由大语言模型生成的质量评估字段, 目前采用 DeepSeek-V3.2, 相关提示词记录如下以便复现与审查, 以后也会使用其他模型. 需要注意的是评分结果在多次测试中波动较大, 仅供参考. `阅读状态` 是一个读者字段, 用于个性化记录阅读进程. 读者可以手动编辑该字段, 但是如果希望在使用 Git 更新文档内容时不覆盖此字段, 则需通过 `git pull --rebase --autostash` 的方式进行同步
> - 在数学文档的结构上, 理想情况是将所有页面分为目录, 定义和命题三种基本类型. 其中目录用于串联某一主题下的相关定义与命题, 定义用于对概念作正式表述, 而命题用于阐述概念的性质以及不同概念之间的关系等. 但是考虑到实际复杂性, 不可能将所有命题都单独作为文件, 只能选择一些重要的定理, 其余较为次要的命题则嵌入在相关对象的词条文件中进行表述
> - 在数学的知识框架上, 本文档倾向于在集合论或者范畴论的基础上一步步构造, 就像布尔巴基学派在集合论的基础上用公理方法重新构造整个现代数学, 认为数学有三种基本的抽象结构: 代数结构, 序结构, 拓扑结构, 无非就是集合元素的运算, 集合元素的大小, 集合子集的关系. 粗略的说数学入门过程是自然数与计数排序, 整数与数论, 有理数与代数, 实数复数与几何分析拓扑, 从有限到无限, 从离散到连续, 这也是本文档第一阶段的中心思想. 本文档虽然暂时在深度和严谨性上不如专业的书籍资料, 但是在一致性和连续性上绝对是独一无二的, 尤其是中文语境
> - 在具体的内容创作上, 每个概念词条基本上遵循一个潜在的规范, 具体来说, 就是把主体段落分为三个部分: 第一部分给出概念简洁直观通俗的描述, 使读者能够迅速把握其核心含义; 第二部分集中列出该概念相关的重要性质与基本命题, 用以刻画其在理论结构中的位置; 第三部分则给出相对严格形式化的定义, 作为概念在数学体系中的最终落脚点. 通过这种分层结构, 读者可以在不深入细节的情况下, 对一个概念形成整体印象. 另外为了格式紧凑, 主体段落尽量使用简化的符号表达, 而完整形式化的符号定义单独另起缩进段落
> - 数学文档的第二阶段将大致划分为数理逻辑, 纯数学与应用数学三个方向. 其中, 数理逻辑主要包括经典的模型论, 证明论, 递归论, 集合论, 以及与之密切相关的范畴论. 纯数学方向涵盖高等数论, 高等代数, 高等几何, 高等拓扑与高等分析等核心领域. 应用数学方向则侧重于计算与算法, 方程与模型, 优化与控制, 组合与设计, 统计与信息, 以及计量与金融等应用性学科, 旨在建立数学理论与实际问题之间的系统联系
